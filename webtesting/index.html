Fetching and keys

Browsers can't read another site's HTML directly unless that site allows it, so pages are fetched through a read proxy. This deployment ships its own: it refuses private and link-local addresses, re-checks every redirect hop, and caps what it will download. The public proxies are kept only as a fallback — they are rate limited and see every URL you audit. Point “My proxy” at your own if you need to reach a host this one can't.

The fix plan is requested through this site's own endpoint, never straight from your browser to Anthropic. If the deployment has an API key configured, leave the key field empty. If it doesn't, a key typed here is forwarded for that one request and is never stored.

Can't fetch? Audit pasted source instead

If proxies are blocked, open the page in a browser, use View Source (Ctrl+U), copy everything and paste it here. Every check still runs, layout is still measured from the real stylesheets, and no network access is needed. Link checking is skipped unless you turn it on.

      Responsiveness is measured, not guessed: each sampled page is re-rendered in a hidden frame at 390, 768 and 1280px with its own stylesheets but with scripts removed, then real geometry is read back — document width, overflowing elements, tap target sizes, computed font sizes. Because scripts are stripped, layout that JavaScript builds after load is not measured, and a page whose CSS fails to load into the frame is reported as unmeasured rather than passing.

      Weight, layout shift and largest paint are measured, not modelled: assets are weighed by fetching them, and CLS and LCP come from performance observers running inside the render frame. Because that frame has the site's scripts stripped, those two are a floor — the real figures with your JavaScript running will be the same or worse. Interaction responsiveness (INP) is not measured at all, since it needs your own scripts executing under throttling; nor is anything that depends on a live session, an inbox or a real device. Those become a checklist under “needs a human” rather than a silent pass.

      Image and font bytes can only be read where a route reports real binary weight, meaning this site's proxy, direct CORS, or your own proxy. Through the public text proxies they are reported as unweighable rather than as zero.

      Pages are rendered for measurement inside sandboxed frames with their scripts removed by parsing, not by pattern-matching. The frame that reads geometry cannot execute anything; the separate frame that measures layout shift can execute only our own probe and reports back by message, because it has no access to this page.

      What this can't see: real load timings and Core Web Vitals from the field, colour contrast defined in external stylesheets, and pages behind a login. Treat scores as a triage order, not a grade — read the findings.

      If proxies are blocked, use “Audit pasted source” in the console: paste the page source and every rule still runs, layout is still measured from the page's real stylesheets, and no network access is needed. With an API key, Claude also reads the copy and quotes the typos, punctuation errors and pasted-in-the-wrong-place sentences that no rule can catch.

      Deep link: append ?url=https://example.com/&pages=25&depth=2&run=1 to this page's address to audit on load. Also accepted: mode, proxy, devices, landscape, links, sub, resp, perf, forms, sec. If the target URL has its own query string, percent-encode it — encodeURIComponent(url) — or any bare ampersand after the first is read as a parameter of this tool. API keys are never accepted from the address bar.

      Links and resources are checked together — images, scripts, stylesheets, iframes and form actions as well as anchors — and each broken target is listed with every page that references it and the link text used. Checks that fail because a proxy was blocked or rate limited are reported as unverified, never as broken.
